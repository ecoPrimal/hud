    3. What’s Missing: Epitope Sort Layout

    3.1 The Problem

    The HUD uses a fixed grid layout. Panels are arranged by the developer’s architectural intuition, not by the user’s behavioral affinity. When a human looks at the HUD, their attention clusters around what interests them â€” which is an epitope, not a grid position.

    3.2 Epitope Sort as Layout Engine

    The compression inequality:

    H(data|epitope) < H(data|alphabet) < H(data)

    Applied to layout:

    • H(layout|alphabet) â€” panels arranged alphabetically or architecturally. Maximum cognitive load.
    • H(layout|epitope) â€” panels arranged by behavioral affinity. Minimum cognitive load for THIS viewer.
    • H(layout) â€” random arrangement. Maximum entropy.

    The epitope sort layout:

    1. Track which panels the viewer looks at (eye-tracking, scroll position, click frequency)
    2. Cluster panels by co-attention (panels viewed together drift together)
    3. Re-sort the layout so that behaviorally related panels are spatially adjacent
    4. The layout EVOLVES per viewer archetype (epitope) â€” not per individual (that would be identity tracking, which we don’t do)
