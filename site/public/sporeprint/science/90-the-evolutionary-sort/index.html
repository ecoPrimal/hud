    Paper 90: The Evolutionary Sort

    Feed 45,470 files through Shannon entropy and sigmoid classification. Watch the codebase self-sort into evolutionary body plans. The organism is 98% invertebrate. Only 473 files have internal skeletons. The spider body plan does not exist in code. That gap is a wedge.

    Method

    No labels. No training set. No instructions on what to find.

    Feed every source file (45,470 files, 11,051,393 lines) through:

    1. Shannon entropy â€” information density per file (H = -S p log2 p)
    2. Vocabulary richness â€” unique words / total words
    3. Feature counting â€” types (enums, structs, classes), functions, imports
    4. Sigmoid classification â€” smooth S-curve boundaries mapping features to [0,1]

    Then let the sigmoid sort each file into one of seven evolutionary body plans:

    Finding 1: Jellyfish Dominates (58.6%)

    21,220 files. 6.47 million lines. Nearly 60% of the entire codebase.

    Jellyfish are the most successful body plan on Earth by biomass. They are also the most successful body plan in code. A jellyfish file has:

    • High Shannon entropy â€” it’s complex, information-dense
    • No internal skeleton â€” zero types (no enums, no structs, no classes)
    • Reactive â€” event-driven, nerve-net behavior, no centralized control

    The markdown documentation (13,431 files), most Rust files (6,428), all Python without classes (396). These are nerve net: they react to stimuli, pass signals, process information â€” but they have no bones. No defined types. No schema. All reaction, no skeleton.

    This is biologically correct. On Earth, jellyfish have survived for 500 million years. They outpersist every vertebrate. They don’t need bones because they’re carried by the medium itself (water). Jellyfish code doesn’t need types because it’s carried by the runtime itself.

    Finding 2: Vertebrate Is Rare (2%)

    Only 473 files out of 45,470 have internal skeletons â€” defined types, functions, imports, and complexity all present simultaneously. That’s 1%.

    The vertebrate exemplars:

    These are files with real internal structure â€” the type system IS the skeleton that everything else hangs on. On Earth, vertebrates represent less than 5% of all animal species. In this codebase, vertebrate files represent 2% of files and 1% by count. The proportion is biologically accurate without being told.

    Vertebrate is Rust-only. No JavaScript, Python, Shell, TOML, Markdown, or HTML file ever reaches the vertebrate stage. Only Rust produces internal skeletons. This confirms the Jellystein hypothesis: JS is the jellyfish (nerve net, no bones), Rust is the vertebrate (internal skeleton), and the bones are underneath.

    Finding 3: Spider = Zero Files (THE GAP)

    Zero files classified as spider. The spider body plan â€” few segments, highly specialized appendages, hard exoskeleton â€” does not exist in code.

    Why? Code transitions from:

    • No skeleton (jellyfish) ? many segments (millipede) ? internal skeleton (vertebrate)

    There is no intermediate stage of “few specialized appendages with a hard external shell.” In biology, spiders evolved their body plan by fusing segments and specializing appendages (8 legs, spinnerets, fangs â€” each different). In code, there’s no equivalent: you either have many similar functions (millipede) or you have types (vertebrate). The “few but highly specialized with external protection” niche is empty.

    The spider gap is a wedge (Paper 88, ?). It’s the place where a new body plan could grow. What would a spider-pattern file look like? Perhaps: few functions, but each one with strong type constraints (generics, trait bounds) â€” specialization without proliferation. A file with 3-4 functions that are each heavily parameterized. Few legs, but each leg does something different.

    Finding 4: Centipede Is Prime

    2,113 files classified as centipede. 2,113 is prime â€” it divides only by 1 and itself.

    The centipede body plan (one function per segment, each segment long, Unix philosophy) has a prime count. It wobbles naturally on the p-remainder (0.5888). Meanwhile:

    • Jellyfish count (21,220) has 12 divisors â€” OVER-STABLE
    • Millipede count (8,846) has 4 divisors â€” stable
    • Vertebrate count (473) has 4 divisors â€” stable

    The most rigid body plan (one appendage per segment, no variation) produced a prime count. The most flexible body plan (no skeleton, all nerve net) produced the most-divisible count. Rigidity ? prime. Flexibility ? composite. The p-stability metric from Paper B-9 predicted this.

    The Klein Bottle Self-Sort

    The evolutionary sort is not a snapshot. On a Klein bottle, outputs fold back as inputs. The sort runs, produces a classification, and that classification feeds back into the next sort. The organism watches itself evolve.

    The klein-evolve.sh daemon:

    1. Runs vitruvian-evolve.py periodically
    2. Writes evolve-state.json to the membrane feeds
    3. Compares to the previous sort (the fold: output ? input)
    4. Detects drift: files changing stage, new files appearing, fossils going extinct
    5. The delta IS the evolution. The comparison IS the natural selection.

    The Klein bottle IS the self-sort. The inside-out donut sorts itself by reading its own output and feeding it back as input. The organism doesn’t just have a body plan â€” it watches its body plan change.
