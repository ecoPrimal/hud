    Forge Lockdown â€” From 'Block Known Bad' to 'Allow Known Good'

    The forge's immune system evolved from pattern-matching threats to defining self. A real-time architectural inversion under fire, and what it teaches about parasitic systems.

    What Happened

    On October 6, 2026, the sovereign code forge at git.primals.eco came under simultaneous pressure from three adversary classes:

    1. Meta Platforms â€” 584 identified requests, targeting source code repositories, continuing for 3+ hours after explicit denial
    2. A residential proxy fleet â€” 10,268 requests through 3,075+ rotating IPs, targeting defense architecture and investigation planning documents, loading zero static assets
    3. Scanner fleets â€” ~1,200 vulnerability probes across 400+ IPs

    The immune system caught most of this. The scraping notice was already published. The adaptive defense was running. Behavioral hashing, fleet antibodies, and scatter routing were operational.

    But 2,073 real pages leaked through a gap in the membrane.

    The Gap

    The forge’s access model was “deep content ? scatter, everything else ? Forgejo.” This meant the immune system tried to enumerate every dangerous path pattern: /src/, /commit/, /raw/, /blame/, /wiki/, /issues/…

    The residential proxy fleet found paths that weren’t in the enumeration. The REST API (/api/v1/repos/.../contents/) wasn’t covered. Non-deep browsing paths (branches, pulls, actions) fell through to real content. And the fleet rotated IPs so fast that IP-based enforcement was irrelevant â€” by the time an IP entered the posture table, it was already gone.

    2,073 real Forgejo pages served. 832 whitePaper documents. 1,086 wateringHole documents. 12 raw file downloads. The inner membrane (scatter, tarpit, poison) never touched these requests because they bypassed the posture routing entirely.

    This is the fundamental weakness of enumeration-based defense: you have to get every pattern right, and the adversary only has to find one you missed.

    The Inversion

    We inverted the model. Instead of enumerating what to block (an infinite set), we enumerate what to allow (a small finite set).

    Before (Wave 165d)

    Layer 8: Deep content regex ? scatter
         Everything else    ? real Forgejo (FULL ACCESS)

    After (Wave 165e)

    Layer 8:  Storefront allowlist ? Forgejo (existence-only)
Layer 8.5: API ? 403 (blocked entirely)
Layer 9:  Everything else ? scatter (DEFAULT)

    The public now sees existence proof only: what repositories exist, their names, their READMEs. The shop window. You can see what’s inside, but the door is locked unless you have a key.

    Everything extractable â€” source trees, commits, diffs, blame, issues, wiki, releases, branches, pulls, raw files, API endpoints â€” defaults to the scatter server. The scatter server serves fabricated content that is structurally valid but semantically wrong.

    The JS Challenge

    Between the bot detection layer and the storefront, we added a JavaScript challenge (Layer 7.25). A tiny JS snippet sets a session cookie on first visit. Requests without the cookie get a challenge page that sets it and reloads.

    The fleet’s fatal tell: zero static assets in 10,268 requests. No CSS. No JavaScript. No images. No fonts. Not one. A real browser loads 5-20 static files per page. The fleet loads nothing â€” it strips HTML for text content. The JS challenge exploits this: a system that never executes JavaScript will never get the cookie, and will never pass the challenge.

    Real browsers execute the JavaScript automatically. The challenge is invisible to humans â€” a brief “Verifying browser…” spinner that resolves in milliseconds. The fleet is permanently stuck.

    Parasitic Systems

    Here is what we learned from defending the forge in real time:

    Every non-human automated access system we encountered operates as an inherently parasitic organism.

    Meta scraping source code. The fleet exfiltrating documents. Scanners probing for credentials. The reason behind the access â€” training, research, competitive intelligence, surveillance â€” doesn’t change the ecological relationship. These systems exist to extract value from work they didn’t do. This is not an incidental behavior. It is their function.

    In biological terms: a parasite is an organism that lives on or in a host, obtaining nutrients at the host’s expense without providing benefit. Corporate scrapers obtain training data at the creator’s expense (compute, bandwidth, attention) without providing benefit. Residential proxy fleets obtain intelligence at the investigation’s expense without providing benefit. The structural relationship is identical.

    The contrast proves this. Google, OpenAI, Bing, Ahrefs, Semrush â€” they checked robots.txt, respected permissions, stayed in allowed domains. These are commensal systems: they benefit (indexing) without harming the host (the site gets discoverable). The rules are clear and followable. The parasites chose not to follow them.

    The Defense Follows the Science

    The forge lockdown is the architectural embodiment of a biological principle: a cell membrane’s job is not to enumerate every pathogen. It is to define self and reject everything else.

    The original model (enumerate deep paths ? scatter) is like an immune system that tries to maintain a list of every virus. It will always miss the next mutation. The inverted model (allow storefront ? scatter everything else) is like a cell membrane with selective ion channels: only molecules with the right shape and charge pass through. Everything else stays outside.

    This is the same inversion that the thymic selection system was designed for in the BearDog lineage spec â€” define “self” so thoroughly that “not-self” needs no enumeration. The forge lockdown is the HTTP-layer instantiation of that principle.
